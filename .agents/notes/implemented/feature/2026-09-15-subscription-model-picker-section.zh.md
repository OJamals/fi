# Agent Note: composer 模型选择器中的订阅提供方

Status: implemented

[English](2026-09-15-subscription-model-picker-section.md) | 中文

## 问题

composer 模型选择器把所有 Host 目录分组放在一份未区分的列表里。用户无法判断哪些路由使用已有订阅授权，哪些路由需要普通 API-key 配置。Antigravity 适配器还公布 `Antigravity`，而其他订阅路由显示为小写路由名称。

## 决定

通用客户端模型选择插件持有仅供显示的注册服务 `ctx.modelSubscriptions`，并把匹配且可见的分组集中放在 composer Model 面板底部、带标签的分区。FI 登录客户端插件从用于生成订阅登录凭据键的同一路由列表贡献 `anthropic`、`openai-codex`、`xai` 和 `antigravity`。普通分组在分区上方保持 Host 目录顺序；匹配分组在分区内部也保持 Host 顺序。空白或重复的注册 id 在注册时失败。没有已注册的订阅分组含可见模型时，分区消失；撤销贡献后选择器立即更新。

Antigravity 适配器以小写路由 id 公布目录提供方名称。Models 的“添加提供方”目录项和登录标签保留各自的显示名称。分组不更改提供方或模型 id、认证操作、推理路由、持久 Session 事件或 `/model` 弹窗顺序。搜索在呈现前过滤两个分区，键盘导航遵循显示的行顺序。

## 考虑过的替代方案

**排序 Host 模型目录。** 这会改变 `/model` 和所有其他目录消费者，但订阅分组只属于 composer 的呈现需求。

**在通用选择器中硬编码 FI 路由 id。** 这会把上游所属的客户端包绑定到 FI 提供方列表，也使其他组合无法选择自己的订阅路由。

**给每个订阅提供方加标记。** 逐行标签会增加紧凑选择器中的视觉干扰，却不会为这些服务提供列表中的独立位置。

## 后果

底部分区让订阅路由容易识别，同时保留确切的选择和目录语义。FI 登录列表同时负责登录和选择器分组的路由，因此没有第二份可能漂移的配置身份列表。客户端包增加一个可撤销的注册服务和一个本地化分区标签。无密钥浏览器证据覆盖桌面与窄视口的分区；单元测试覆盖四条路由 id、实时注册、搜索和不变的弹窗顺序。
