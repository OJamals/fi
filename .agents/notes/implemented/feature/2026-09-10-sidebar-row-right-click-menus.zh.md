# Agent Note: 侧栏行右键菜单

Status: implemented

[English](2026-09-10-sidebar-row-right-click-menus.md) | 中文

## 问题

侧栏的 Workspace 行与 Session 行的行内操作（重命名/删除、重命名/分叉/归档）只藏在悬停显示的 `...` 按钮后面，指针用户必须先悬停才能触及。右击行毫无反应：行没有任何 `contextmenu` 处理，而 Electron 外壳的原生上下文菜单只覆盖可编辑文本与选区，桌面平台承诺的交互恰好在用户最期待之处缺失。

## 决策

在拥有菜单的行上右击，会在指针处打开同样的 `Menu` 菜单项。`ProjectRowItem` 与 `SessionNodeItem`（packages/client/ui-workspace/src/client/rows/Rows.tsx）在 `...` 按钮渲染的同一条件下附加 `onContextMenu` 处理器（真实 Workspace 行；非空白 Session 行）：它抑制默认菜单，把指针坐标记录到 ref 中，并打开既有菜单。菜单通过新增使用的 `getAnchorRect`（`Menu` 原语既有能力）在记录点返回零尺寸 `DOMRect`，使传送门列表如原生上下文菜单般固定在指针处；坐标点在关闭与每次 `...` 点击时清除，按钮锚定布局保持不变。没有菜单的行（Ungrouped 桶、空白 New Session 行）不附加处理器，右击留给宿主。

## 备选方案

**为行内操作复用 Electron 原生菜单。** 这些操作是基于客户端状态的客户端动作（重命名对话框、fork、归档集合回声）；主进程菜单需要一条重复实现它们的 IPC 通道，且 Web 客户端仍然缺少这一交互。

**右击时在 `...` 按钮处锚定打开。** 菜单项相同但没有原生质感：菜单会出现在按钮位置，在宽行上可能远离指针。

**专门的上下文菜单组件。** 在 `Menu` 原语之外实现第二套菜单，或引入页面级 contextmenu 中介，都会重复原语已经拥有的锚定、关闭与无障碍能力；行本身已拥有各自的菜单项列表。

## 后果

Web 客户端与桌面端（渲染同一客户端）都无需悬停即可触及行内操作；`...` 按钮保持其测量锚定布局，`Menu` 既有的 Escape/外部按下关闭同样作用于指针定位的列表。Electron 外壳的原生上下文菜单继续处理可编辑文本与选区；由于 Electron 不管渲染器是否 `preventDefault` 都会发出 `context-menu` 事件，在行内文本选区上右击时原生复制菜单可能与行菜单同时出现——这是接受的边缘情况，因为选区复制在那里仍有价值。上游合并面：两个行组件、对应测试，以及每份 README 中各一句话。
