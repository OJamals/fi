# Agent Note: 模型通用的首次运行设置

Status: implemented

[English](2026-09-10-model-universal-onboarding.md) | 中文

## 问题

首次运行的引导步骤预设了 DeepSeek 官方提供方。它的 readiness join 专门特判 `deepseek-official` 行——其他任何提供方的事实都会让步骤静默结束——而可见的步骤索要 DeepSeek API Key，在引导模态框内复用模型页的凭据编辑器。尚无提供方的 fi 用户被直接引导到单一厂商的 Key 输入框，而 join 仅为只读或凭据不可读的用户则被跳过，没有任何通往设置界面的路径。

## 决策

该步骤提供方中立，只做路由而不收集凭据。`onboardingReadiness` 现在只回答一个问题——用户是否已经能和某个模型对话——数据来自模型页读取的同一份 provider/settings/credential join：任何可用提供方都结束步骤；没有任何可用提供方时（旧流程视为应跳过的每一种原因：提供方未启用、凭据不可读、设置只读），都显示该步骤；只有 join 加载失败、或目录中根本没有可配置提供方时才跳过，因为这两者无法从设置界面采取行动。步骤本身（`ModelSetupDialog`，槽 id `model-setup`，取代 `deepseek-official`）展示中立文案，主操作完成步骤并通过外壳既有的 `openSection` 接口路由到模型分区，次操作推迟设置。引导中不输入任何凭据：模型页对未配置的提供方会自动展开其设置卡片，被引导的用户在那里输入 Key——适用于任何提供方，内置或自建。

`agent-default-model` 组合行及其设置分区保持不变：默认选择仍是无显式选择时创建 Agent 的底层机制，保存的选择仍会覆盖它。提示词、persona 与路由层不提及任何厂商。

## 备选方案

**继续在模态框中收集官方 Key。** 它在产品应当提供方中立的时刻预设了单一厂商，且推迟设置的用户只剩一个失效的默认提供方，毫无路径。

**在引导中收集提供方无关的 Key 输入框。** 没有“这是哪家提供方的 Key？”的答案，除非列出提供方清单；且该输入框会复制模型页的编辑器——而那个页面的职责正是这份 join。

**像以前一样，在只读或不可读的 join 上自动完成。** 这些状态描述的是单个提供方的可修复性，而不是用户的状态；步骤路由到的模型页在每一种状态下都可行动，而被跳过的首次运行用户无从得知设置的存在。

## 后果

首次运行不再把用户导向 DeepSeek：声明之后是一个中立的设置步骤，路由到设置 → 模型，Key 在那里写入（e2e 现在通过该页自动展开的设置卡片完成 Key 写入）。步骤 id 从 `deepseek-official` 改为 `model-setup`，随内嵌编辑器一起，词典中的 `onboardingSave`/`onboardingSaving` 键被移除。未启用、凭据不可读与只读的 join 现在会显示该步骤（此前是跳过）——每一种都能在步骤路由到的页面内解决或诊断。web e2e 场景 `onboarding-deepseek-config` 更名为 `onboarding-model-setup`，golden 一并更新。推迟设置又直接开启会话的用户仍会到达默认选择的提供方并遇到其凭据错误；该错误的路由是后续工作。
